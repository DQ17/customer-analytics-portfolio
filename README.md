# Customer Analytics Portfolio Project

Real transaction-level data from a UK-based online gift retailer (Dec 2010 - Dec 2011,
~540k line items), analyzed twice — once in SQL, once in Python (pandas) — to answer
real business questions about customers, revenue, and retention, and to compare how
the same analysis reads in each tool.

Dataset: [UCI Online Retail](https://archive.ics.uci.edu/dataset/352/online+retail)

## Project structure

```
data/
  online_retail.xlsx        raw source file (not committed, see Setup)
  customer_analytics.db     SQLite database built from it (not committed, see Setup)
  sample_250_rows.csv       a random sample of the cleaned data, for a quick look
sql/
  analysis_queries.sql      every business question, in SQL, against the retail_clean view
scripts/
  load_data.py              xlsx -> cleaned SQLite table
  rfm_analysis.py           customer segmentation (RFM) + charts
  python_analysis.py        the same 11 business questions as analysis_queries.sql, in pandas
  dashboard.py              interactive Streamlit dashboard (reads live from the SQLite db)
docs/
  step_by_step_guide.md     a full walkthrough of the pipeline, written while building this
outputs/                    CSV + PNG results from both the SQL and Python analysis
```

## Setup

```bash
pip install -r requirements.txt
python scripts/load_data.py       # builds the database from the raw xlsx (run once)
python scripts/rfm_analysis.py    # runs the RFM segmentation + charts
python scripts/python_analysis.py # runs the full pandas analysis (mirrors the SQL file)
streamlit run scripts/dashboard.py # launches the interactive dashboard at localhost:8501
```

`sql/analysis_queries.sql` can be run against `data/customer_analytics.db` with any
SQLite client (DB Browser for SQLite, a VS Code SQLite extension, or the `sqlite3` CLI):

```bash
sqlite3 data/customer_analytics.db ".read sql/analysis_queries.sql"
```

Note: the raw `online_retail.xlsx` and the built `customer_analytics.db` aren't committed
to this repo (they're regenerated by `load_data.py`) — see `.gitignore`.

## Data notes (things that had to be cleaned/handled)

- ~135k of 542k rows have no `customer_id` (guest/unlinked transactions) — excluded
  from customer-level analysis, kept for revenue totals.
- Invoice numbers starting with "C" are cancellations — flagged as `is_cancellation`.
  In practice, every cancellation already has a negative quantity, so the `retail_clean`
  view's `quantity > 0` filter removes them without needing a separate check.
- ~1,336 rows had a negative quantity without being a flagged cancellation, and ~2,517
  had a zero/negative price (likely bad-debt or adjustment entries) — both excluded.
- ~4,993 exact duplicate line items were removed via `SELECT DISTINCT`.
- Added a computed `line_total` column (`quantity * unit_price`), since it's not in
  the raw data.

All of the above is implemented once, as a SQL view (`retail_clean`), so both the SQL
queries and the Python analysis start from the same already-cleaned data.

## Business questions this answers

Implemented identically in both `sql/analysis_queries.sql` and `scripts/python_analysis.py`:

1. **Revenue trend** — is the business growing month over month?
2. **Top customers** — by total spend, and separately by order count.
3. **Best sellers** — which products move the most volume?
4. **Customer segments (RFM)** — who are our Champions, who's At Risk of churning,
   who's already Lost? The kind of segmentation real marketing/retention teams use
   to decide who gets a discount email vs. a win-back campaign.
5. **Repeat purchase rate** — what % of customers ever come back?
6. **Geographic breakdown** — which countries drive the most customers/revenue?
7. **Market basket** — which pairs of products are most often bought together.
8. **New vs. returning customer revenue** — how much of each month's revenue comes
   from brand-new customers vs. customers who'd already bought before.
9. **Cohort retention** — of the customers who first bought in a given month, what
   % were still buying 1, 2, 3... months later?

## Dashboard

`scripts/dashboard.py` is an interactive Streamlit dashboard, filterable by country, showing:
revenue KPIs, monthly revenue trend, top customers/products, RFM segment breakdown, and a
cohort retention heatmap. It queries `data/customer_analytics.db` directly (not a saved
snapshot), so it always reflects the current state of the database.

```bash
streamlit run scripts/dashboard.py
```
